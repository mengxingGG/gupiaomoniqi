# 1.1.2：历史委托与成交记录修复

日期：2026-10-16。Android versionName 1.1.2，versionCode 10。

这是针对用户反馈的 1.1.0 起出现、1.1.1 未修复的问题发布的正式修复版。此前对历史标的停用场景的验收有遗漏。保留 1.1.1 标签和发行资产，通过独立 1.1.2 记录问题和修复。

## 原因与修复

真实行情完整扫描会将本轮未出现的旧标的标记为停用，数据库仍保留其股票资料、订单和持仓。旧订单转换代码却使用只返回活跃股票的查询，一笔历史委托引用停用标的就触发 `REAL_ORDER_INSTRUMENT_NOT_FOUND`，使整个委托列表返回 HTTP 500。撤单提交后的响应转换也会触发同一错误，持仓展示还会跳过停用标的。

账本展示现改用保留历史标的的查询，覆盖委托列表、幂等重试、撤单响应与持仓估值；停用标的按已有报价计算持仓价值，不生成新报价。新下单与撮合仍要求标的活跃，不会因读取历史资料而重新放开交易。无需数据库迁移或清空订单、持仓、资金。

Android 此前把成交和委托绑定在同一个失败即取消的并发任务中，委托失败会连带丢弃成功的成交响应。现在分别收集结果、展示各自错误，失败时保留已有记录，成功重试会清除对应错误；登录失效与协程取消仍按原规则处理。读取失败不再同时显示“暂无成交”或“暂无订单”。手动刷新与后台刷新均使用此处理。

如果只安装新 APK、服务端仍旧，成交页已可独立使用；委托页会明确提示服务端需要更新到 1.1.2，不能仅凭 APK 恢复旧服务端的历史委托接口。
