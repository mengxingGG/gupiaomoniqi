# 运行性能与账户恢复

本次源码发布版本为 `1.0.3`；Android 使用 `versionCode 7`，需与后端和 Web 协同发布。

生产 API 与应用更新地址固定为 `https://gupiaomoniqi.org`。Android 正式包忽略历史保存的自定义服务器地址，设置页只展示官方服务和应用更新入口；仅调试包允许通过 ADB 临时覆盖地址。

## 本次故障的根因

V8 在约 4096 MB 堆上限处退出只是最后一道保护。真正的启动雪崩来自虚拟盘分钟 K 线：旧实现会把最近数日、每只股票的全部分钟线一次性查询并复制到 JavaScript `Map`。1200 只股票连续运行三天可产生约 518 万条分钟线，查询结果、缓存对象和 PGlite 工作内存叠加后足以撞上 4 GB。

当前实现保留 4 GB 安全围栏，并做以下收敛：

- 数据库每只虚拟股票只保留最近 240 个分钟点；超过 24 小时的分钟点会直接清理。
- 启动时每个周期只加载最新一条 K 线；进程内每个序列只保留最近 2 条热快照。
- 图表历史按“单只股票 + 所需周期”查询，不再全市场回灌。
- 批量清理只向 Node 返回一条计数，不再用 `DELETE ... RETURNING 1` 物化几百万条结果。
- 规则 AI 选股每次最多评估 48 个分散样本，不再为每个交易者复制并排序整个股票池。
- `aiBacklog` 继续作为告警指标，但不再单独触发降载。旧逻辑会因积压而减少吞吐，形成永久 CRITICAL 的反馈环。
- 真实行情全市场默认 5 分钟扫一轮；自选、持仓、详情和挂单所在热页仍按秒刷新。

Windows 启动器和 Linux systemd 单元都显式设置 `--max-old-space-size=4096`。不要把提高到 8192 MB 当作本问题的主要修复；只有在确认堆曲线已经稳定、机器仍需更大业务工作集时才应调整。

## 可调运行参数

以下环境变量可按服务器能力覆盖默认值：

| 变量 | 默认值 | 作用 |
| --- | ---: | --- |
| `AI_TRADER_COUNT` | 按 CPU/内存自动选择，最高 5000 | 规则 AI 总人口 |
| `AI_ACTIVE_PER_ROUND` | 按机器自动选择 | 每轮最多处理人数 |
| `AI_ROUND_INTERVAL_MS` | 按机器自动选择 | AI 轮次间隔 |
| `REAL_MARKET_CONCURRENCY` | 2 | 全市场请求并发 |
| `REAL_MARKET_FULL_SWEEP_MS` | 300000 | 全市场目标扫描周期 |
| `REAL_MARKET_HOT_REFRESH_MS` | 1000 | 热页刷新周期 |
| `REAL_MARKET_HOT_PAGES_PER_ROUND` | 1 | 每轮热页数量 |

四核机器建议先保持默认值观察，不要同时提高 AI 每轮人数、真实行情并发和全市场刷新频率。

## 持久配置路径

根配置只通过 `resolveRootConfigPath()` 解析，优先级为：调用方显式路径、`APP_CONFIG_PATH`、工作目录下的 `config.json`。读取不存在的文件会返回 `MISSING` 并安全停用相关能力，不会调用 `fs.watch` 监听一个不存在的目标，也不会因为 `ENOENT` 终止进程。

Linux systemd 单元已固定设置：

```text
APP_CONFIG_PATH=/var/lib/gupiaomoniqi/config.json
```

部署时把配置放入持久目录，并仅允许服务账户读取：

```bash
sudo install -m 0600 -o gupiaomoniqi -g gupiaomoniqi \
  config.json /var/lib/gupiaomoniqi/config.json
sudo systemctl restart gupiaomoniqi
```

当前根配置在进程启动时读取；修改后使用受控重启生效。Windows `Run-App.ps1` 已把 `APP_CONFIG_PATH` 指向其持久数据目录。

## 邮箱验证码找回

新账户包含昵称、用户名、邮箱和密码。登录可输入用户名或邮箱。找回接口只发送邮件，不读取或接收用户邮件：

- 验证码固定为 6 位数字，有效期 10 分钟。
- 每个验证码最多尝试 5 次，新验证码会使旧验证码失效。
- 数据库只保存 scrypt 哈希，不保存验证码明文。
- 请求未知邮箱时返回与已注册邮箱相同的接受响应，避免泄露账户是否存在。
- 密码重置成功后撤销该账户的全部旧会话。
- 请求接口同时按 IP 和邮箱限流。

### 新账户注册验证

Web 与 Android 注册分两步完成：先调用 `/api/account/email-verification/request` 发送注册验证码，再调用 `/api/account/email-verification/confirm` 校验。服务端校验成功后签发短期、一次性的注册凭证，`/api/auth/register` 在数据库事务内消费凭证并创建账户：

- 注册凭证与规范化邮箱绑定，不能换邮箱使用。
- 验证码与凭证都在 10 分钟后失效，每个验证码最多尝试 5 次。
- 挑战记录持久化，服务受控重启后仍可继续验证。
- 注册事务失败时不会错误消耗凭证；成功后同一凭证不可重复建号。
- 生产环境强制验证邮箱；SMTP 未配置时明确返回 503，不会静默跳过。

### 旧账户补充邮箱

迁移前创建、`email` 为空的账户在用户名登录或自动恢复登录状态后，Web 与 Android 都会显示不可关闭的补录卡片；用户仍可选择退出当前账户。补录不是直接写数据库，而是先向待绑定邮箱发送六位码，再由服务端校验并原子绑定：

- 卡片会等 `/api/auth/me` 返回最新账户资料后再判断，避免只相信客户端旧缓存。
- 验证码有效期 10 分钟、最多尝试 5 次，新请求会使旧验证码失效。
- 已被其他账户使用的邮箱不会暴露归属，只返回“邮箱暂时无法绑定”。
- 该补录入口只允许给空邮箱账户首次绑定，不允许覆盖已有邮箱。
- 服务重启后，未过期验证码仍可继续验证；绑定完成后可以立即用邮箱登录或找回密码。
- SMTP 只承担出站发送，不配置 POP3、IMAP 或任何收件能力。

推荐在持久 `config.json` 中配置 SMTP。QQ 邮箱使用 465 端口、SSL 和邮箱授权码，不要填写网页登录密码：

```json
{
  "smtp": {
    "enabled": true,
    "host": "smtp.qq.com",
    "port": 465,
    "secure": true,
    "requireTls": false,
    "user": "your-account@qq.com",
    "pass": "QQ邮箱SMTP授权码",
    "from": "股票模拟器 <your-account@qq.com>"
  }
}
```

环境变量仍受支持并优先于 `config.json`，便于把密钥放在独立的系统机密文件中：

```text
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_REQUIRE_TLS=true
SMTP_USER=mailer@example.com
SMTP_PASSWORD=应用专用密码
SMTP_FROM=股票模拟器 <mailer@example.com>
```

Linux 部署可写入 `/etc/gupiaomoniqi.env`，并将权限设为仅 root 可读；systemd 单元会自动读取该文件。Windows 计划任务以 `SYSTEM` 运行，应设置机器级环境变量，并在受控重启应用后生效。可用管理员 PowerShell 避免把 SMTP 密码直接写进命令历史：

```powershell
$smtpCredential = Get-Credential
[Environment]::SetEnvironmentVariable("SMTP_HOST", "smtp.example.com", "Machine")
[Environment]::SetEnvironmentVariable("SMTP_PORT", "587", "Machine")
[Environment]::SetEnvironmentVariable("SMTP_SECURE", "false", "Machine")
[Environment]::SetEnvironmentVariable("SMTP_REQUIRE_TLS", "true", "Machine")
[Environment]::SetEnvironmentVariable("SMTP_USER", $smtpCredential.UserName, "Machine")
[Environment]::SetEnvironmentVariable("SMTP_PASSWORD", $smtpCredential.GetNetworkCredential().Password, "Machine")
[Environment]::SetEnvironmentVariable("SMTP_FROM", "股票模拟器 <$($smtpCredential.UserName)>", "Machine")
```

没有配置 SMTP 时，注册验证、旧账户补邮箱和找回接口都会明确返回“邮件发送尚未配置”，不会生成无法送达的验证码。`GET /api/health` 的 `emailDelivery.configured` 可用于部署验收。

## 服务器本机紧急重置

不要只凭来源 IP 开放改密接口。Nginx 或 Cloudflare 反向代理会让公网请求在 Node 看来来自 `127.0.0.1`，单纯信任本机 IP 等同于留下公网改密后门。

应用无法启动时，在服务器本机进入部署目录，通过标准输入传入新密码。脚本直接查询账户表，不会加载行情和 AI 缓存：

```powershell
npm run account:reset-password -- --username hackerxuyun
```

交互模式会隐藏新密码并要求输入两次。自动化 Agent 可改用 `--password-stdin`，密码不会作为命令行参数出现在进程列表中。

也可在同一次操作中给旧账户补绑定邮箱：

```powershell
npm run account:reset-password -- --username hackerxuyun --set-email user@example.com
```

脚本会检查密码强度和邮箱唯一性，更新密码哈希、撤销旧会话并使未使用验证码失效。PGlite 数据目录同一时刻只能由一个进程安全持有；如果应用仍在运行，应先走现有受控停机流程。

## 发布后验收

至少连续观察一个完整全市场扫描周期，并满足：

- 冷启动能到达 `/api/health`，不在 `loading virtual repository` 阶段撞堆上限。
- 稳态 `heapUsed` 不随分钟线数量线性增长。
- `aiBacklog` 可短时升高，但资源压力解除后能回落，不长期停在数千。
- 四核服务器事件循环延迟通常低于 35 ms；持续超过 80 ms 时继续降低 AI 或真实行情频率。
- 注册发码、验证码校验、一次性凭证建号、邮箱登录、旧账户补邮箱、正确重置和旧会话失效全部通过。
