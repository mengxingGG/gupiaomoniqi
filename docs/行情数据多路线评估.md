# 行情数据多路线评估

实测时间：2026-10-16 约 09:56（UTC+8）。测试环境为开发电脑，不代表生产 Linux 网络。

## 当前实现与本轮修复

当前生产采集仍以东方财富为数据源：Node HTTP 为主，Python urllib 为传输回退。这是同一数据源的两条传输路径，不是两个独立数据源。

本轮将 Python 回退从历史行情补齐到列表分片与盘口；保留 Linux `python3` 优先、Windows 专用命令发现，新增显式解释器配置。HTTP 5xx 和网络失败可进入回退；429 不通过换进程绕过限制；取消请求不会继续启动 Python，重试有总时长预算。

原备忘的生产 ENOENT 问题与本地源码版本存在差异。应部署本轮构建后核对 Linux 实际产物，不能只凭 Windows 构建宣称生产已恢复。

## 开发机实测

| 路线 | 请求内容 | 结果 | 观察 |
|---|---|---|---|
| 东方财富 Node | 股票列表、日 K | 约 10 秒后失败 | 不能据此区分网络问题或远端限制 |
| 东方财富 Python | JSON 回退 | 解释器成功启动，网络请求仍失败 | 没有 ENOENT，不等于行情已恢复 |
| 腾讯报价 | sz002594、hk00700、usAAPL | HTTP 200，约 1.49 秒 | 覆盖本次三个样本，不代表全市场 |
| 腾讯日 K | sz002594，qfq，120 参数 | HTTP 200，121 条，约 1.32 秒 | 返回 qfqday；最后一根为当天未收盘数据 |
| 腾讯港股日 K | hk00700，同一 qfq 参数 | HTTP 200，121 条，约 1.09 秒 | 实际返回 day，不可标成前复权 |
| 新浪报价 | sz002594 | HTTP 200，约 1.78 秒 | 与腾讯成交量口径不同 |

腾讯报价样本中 A 股成交量以手表示，新浪同标的以股表示；港股样本又使用股。不同请求时点略有差异，不能拿数值相差约 100 倍认定异常后直接覆盖。成交量单位、金额币种、报价精度、交易时区及复权必须逐市场映射。

接口依据与核对资料：[AKShare 股票文档](https://github.com/akfamily/akshare/blob/main/docs/data/stock/stock.md)、[腾讯历史接口适配源码](https://github.com/akfamily/akshare/blob/main/akshare/stock_feature/stock_hist_tx.py)。这些公开页面接口没有在本项目中验证商业授权或稳定性承诺。

## 可以怎样接入独立备用源

1. 按能力分路由：标的清单、即时报价、分时、历史 K 线、盘口分别声明支持的市场、字段和单位，不能假定每个供应商全覆盖。
2. 建统一字段契约：原始代码映射、币种、单位、时区、复权方式、数据时间和来源；缺失字段保留缺失，不补造为零。
3. 报价整包切换；历史按相同复权口径取完整区间。禁止把前复权与不复权片段拼接，禁止用虚拟行情兜底真实股票。
4. 使用限流、短重试、熔断和定期恢复探测；不逐股票无限串行重试所有路线。失败保留最后成功数据并显示时间。
5. 用真实录制样本核对拆股、除权、休市、跨币种、停牌、空值和成交量，然后再启用自动切换。

腾讯适合作为已验证样本范围内的报价/历史备用候选；新浪可作为 A 股报价交叉核对候选。AKShare 若底层仍调用东方财富，就不构成独立故障域。

上述为接入前的实测评估；当前交付状态以下节为准。

## 2026-10-16 已接入：按股票智能补缺

后续用户明确要求实施自动补缺，以下状态替代上文的候选阶段结论。

- 主源正常的股票保留；缺少报价关键字段或分片行数不足时，只补已识别的缺失股票。整页请求失败时，根据本地已保存的该页股票代码补报价，不向备用源重拉全市场清单。
- 每支股票采用完整报价快照，价格、开高低昨收、量额、时间来自同一个供应商；不会拿东财价格拼接腾讯成交量。
- 路由为东方财富（含 Python 回退）→ 腾讯；腾讯仍未补齐的 A 股才尝试新浪。腾讯成功的标的不再请求新浪。
- 热页仅补当前关注的缺失股票；批量请求最多携带 50 个已确认缺失的代码，不等于全量抓取。并发请求合并、成功缓存 5 秒、失败缓存 15 秒；路线连续网络失败 3 次后冷却 30 秒。
- 提交前再次比较行情时间和主源接收时间；主源已恢复的股票不被晚到的备用结果覆盖。补缺不篡改东财分片失败计数或股票清单来源。
- 历史请求失败、为空或含不完整记录时，只请求该股票所需周期。A 股日/月 K 要求腾讯明确返回 qfqday/qfqmonth，整段原子替换本股该周期的返回区间，不逐字段拼 OHLC，也不影响别的股票。
- A 股五档盘口可在主源失败时切到腾讯整份盘口。港美股报价使用腾讯；英股、其他尚未核验的历史/盘口能力继续保留最后成功数据并提示不可用。
- 报价真实来源写入数据库新增的 data_provider 字段，App/Web 显示备用来源与来源行情时间；服务状态提供补齐数量。时间不伪装成“刚收到即实时”，港美股可能延迟。

当前能力边界：没有本地代码清单的全新市场，无法凭空知道失败页有哪些股票；不通过周末/节假日的日期空隙猜测缺 K 线。对未知标的、未验证复权口径和不支持的周期，明确保留缺失状态。

实际网络验收：10:45 左右适配器仅请求比亚迪，取得腾讯报价、161 根日 K、60 根月 K、五档盘口；请求记录只有 sz002594。报价来源时间 10:44:51，接收约 10:45:34，界面展示前者。自动故障注入验证正常股票不被覆盖、仅缺失代码进入备用源、来源重载持久化、失败分片仍计失败、历史替换不改动其他股票。
