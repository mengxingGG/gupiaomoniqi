# 真实行情模拟盘、全量同步与奖励规则

> 状态：2026-07-28 已进入实现。探针样本的 1200 只证券只用于验证接口，并不是产品股票池上限。

## 1. 产品边界

系统共用一套注册、登录和显示币种偏好，但提供两个物理隔离的模拟盘：

| 模块 | 行情 | 数据库 | 新账户初始资金 |
|---|---|---|---:|
| 虚拟市场模拟盘 | 固定 1200 只证券，由内部行情引擎推进 | `server/data/pgdata/` | US$1,000,000 |
| 真实行情模拟盘 | 东方财富公开批量行情接口返回的全部可用证券 | `server/data/real-pgdata/` | US$1,000,000 |

同一个 `accountId` 可以进入两个盘，但两边分别保存现金、持仓、成交、结算批次和奖励流水。任何一边的买卖或奖励都不得改变另一边的余额。

真实行情模拟盘只使用真实市场数据定价，所有资金、持仓和成交均为模拟数据。它不连接券商，不会发送真实订单，也不涉及真实资金。

## 2. 已验证的东方财富接口

2026-07-28 用户环境探针选择的可用列表端点为：

```text
https://push2.eastmoney.com/webguest/api/qt/clist/get
```

探针当时读取的 `data.total`：

| 市场 | 接口总量 |
|---|---:|
| 沪深 | 5,542 |
| 港股 | 4,699 |
| 美股 | 13,677 |
| 英股 | 8,622 |
| 合计 | 32,540 |

这些数字只是当时快照，程序必须每轮读取 `total` 并动态计算页数，不能写死 300、1200 或 32,540。

单股 `stock/get` 在探针环境中被远端断开，因此当前报价只使用已经验证的 `webguest clist` 批量端点，不向每只股票分别发请求。

历史数据验证结果：

- 日 K：沪深、港股、美股可用；英股样本失败；
- 分时：沪深、港股、英股可用；美股样本失败；
- 缺失历史数据时，只展示数据库中以后持续记录的真实快照，不生成随机 K 线；
- 当前批量端点不含可验证的五档盘口，真实盘明确显示不可用，不使用虚拟盘口冒充。

## 3. 全量证券发现与轮询

首次启动和每轮全市场同步都执行：

1. 并发请求四个市场第一页；
2. 读取每个市场最新 `total`；
3. 按 `ceil(total / pageSize)` 建立全部分页任务；
4. 按配置并发遍历所有分页；
5. 每页成功后立即事务写库，不等待整轮数据全部留在内存；
6. 只有某市场全部分页成功，才把本轮未出现的旧证券标为非活跃；
7. 部分页面失败时保留该页最后一次成功快照，并在状态接口标记降级。

默认配置：

```text
pageSize                 = 100
fullSweepTargetMs        = 10000
concurrency              = 12
hotRefreshIntervalMs     = 1000
hotPagesPerRound         = 8
```

`fullSweepTargetMs` 是目标周期，不伪造性能保证。如果接口响应或本地写库使一轮超过 10 秒，下一轮在上一轮完成后立即开始，状态接口显示实际耗时。

## 4. 自选、持仓与详情页最高优先级

由于可用端点是百股批量列表，而单股报价端点不可用，热更新以“股票当前所在的来源页”为最小请求单位。

优先级从高到低：

1. 正在打开详情页的股票；
2. 所有账户的真实盘自选股，关注人数越多分数越高；
3. 真实盘已有持仓的股票；
4. 当前行情页可见股票；
5. 其余全市场分页。

同一来源页不因多个用户关注而重复请求；热任务与全市场任务同时命中同一页时共享正在进行的网络请求。每账户每个模拟盘最多保存 200 只自选股。

## 5. 本地数据库与容量策略

真实盘必须在本地持久化，应用重启后仍能读取最后成功数据。为避免每 10 秒保存三万多只股票的完整历史而产生数亿行，采用分层存储：

- `real_instruments`：全量证券目录，永久增量更新；
- `real_quotes`：每只证券一行最新真实报价；
- `real_provider_pages`：每页成功时间、失败次数、覆盖数量和错误；
- `real_sync_sweeps`：全市场轮次、页数、覆盖和实际耗时；
- `real_candles DAY`：全量证券每日真实 OHLCV 快照；
- `real_candles MINUTE`：只给自选、持仓和正在浏览的热股票聚合；
- 外部日 K/分时：打开详情页时按需读取并永久缓存；
- 交易账本：`real_portfolios`、`real_positions`、`real_transactions`、`real_position_settlement_lots`；
- 奖励账本：`real_cash_adjustments`，以 `claimId` 唯一。

程序不为真实盘创建虚构股票、随机价格、随机历史 K 线或虚拟盘口。

## 6. 价格、币种与交易

- 沪深来源 CNY，统一报价 CNY；
- 港股来源 HKD，按已记录的导入汇率转换为统一 CNY 报价；
- 美股来源 USD，统一报价 USD；
- 英股接口价格单位为 GBX，先除以 100 得到 GBP，再转换为统一 USD 报价；
- 最终账户统一使用 USD 记账；
- 用户切换 CNY 显示时固定使用 `1 USD = 7 CNY`，不产生换汇交易。

真实盘市价单只允许使用最近成功接收的真实报价。默认超过 120 秒未从提供者成功接收则拒绝下单，避免以失联旧价成交。

交易规则：

- 沪深按 100 股一手、T+1；
- 港股当前按产品统一规则 100 股一手、T+0；
- 美股与英股 1 股一手、T+0；
- 可自由输入手数，或按 25%/50%/75%/100% 资金和可卖持仓计算；
- 手续费、现金、持仓、成交和 T+1 结算批次在一个数据库事务中提交；
- `idempotencyKey` 防止超时重试产生重复成交。

## 7. 签到

- 主页和账户详情页读取同一个签到状态；
- 每个登录账户按 `Asia/Taipei` 自然日只能成功一次；
- 每次奖励 US$100,000；
- 奖励进入点击签到时所在的模拟盘；
- 当天在另一页面或另一模拟盘重复点击返回“已经签到”，不会再次到账。

## 8. 礼包码

| 礼包码 | 奖励 | 规则 |
|---|---:|---|
| `666666` | US$100,000 | 每账户一次 |
| `888888` | US$500,000 | 每账户一次 |
| `#1161125922` | US$1,000,000 | 开发者特权，可无限次 |

礼包码存储于主数据库 `gift_codes`，业务代码不硬编码可扩展礼包列表。新增或更新：

```bash
npm run gift-code:add -- --code NEW2026 --amount-usd 250000 --description 活动礼包
```

可重复礼包：

```bash
npm run gift-code:add -- --code DEVTEST --amount-usd 1000000 --repeatable
```

同一账户对普通礼包的唯一约束是“账户 + 礼包码”。可重复礼包每次用户操作使用新的请求幂等键。

## 9. 跨数据库奖励一致性

登录身份、领取资格和领取状态保存在主数据库，奖励现金写入用户当前选择的账本数据库：

1. 主数据库创建状态为 `PENDING` 的唯一领取记录；
2. 目标账本用领取记录的 `claimId` 写现金调整流水；
3. 同一事务增加可用资金和资金基数；
4. 主数据库把领取记录改为 `COMPLETED`。

如果进程在第 2、3 步之间退出，重试复用同一 `claimId`；目标账本的唯一约束保证不会重复增加现金。

## 10. 路由与状态

- 虚拟盘：`/`、`/stocks/:id`、`/account`；
- 真实盘：`/real`、`/real/stocks/:id`、`/real/account`；
- 状态接口：`GET /api/real-market/status`；
- 行情、图表、账户与交易 API 通过 `mode=VIRTUAL|REAL` 明确选择账本；
- 页面刷新或分享 URL 后不得进入另一模拟盘。

## 11. 运维配置

| 环境变量 | 默认值 | 作用 |
|---|---:|---|
| `REAL_MARKET_SYNC_ENABLED` | `true` | 是否启动真实行情同步 |
| `REAL_DATABASE_DIR` | `server/data/real-pgdata/` | 真实盘独立数据库目录 |
| `REAL_MARKET_PAGE_SIZE` | `100` | 批量列表页大小 |
| `REAL_MARKET_CONCURRENCY` | `12` | 全量同步并发页数 |
| `REAL_MARKET_FULL_SWEEP_MS` | `10000` | 全市场目标周期 |
| `REAL_MARKET_HOT_REFRESH_MS` | `1000` | 热页轮询周期 |
| `REAL_MARKET_HOT_PAGES_PER_ROUND` | `8` | 每轮最多热页 |
| `REAL_MARKET_REQUEST_TIMEOUT_MS` | `8000` | 单请求超时 |
| `REAL_MARKET_QUOTE_MAX_AGE_MS` | `120000` | 下单允许的最大接收年龄 |

临时停用真实同步不会删除数据库；真实盘继续展示最后成功快照并禁止使用过期报价交易。

## 12. 验收

1. 两个 PGlite 目录物理独立；
2. 真实盘从 `total` 动态遍历全部分页，不存在 1200 上限；
3. 同一身份两个盘各自首次获得 US$1,000,000；
4. 任何真实盘操作不改变虚拟盘账本；
5. 真实盘无提供者数据时不出现虚构行情；
6. 自选、持仓与详情页进入热页优先队列；
7. 沪深 T+1，其余市场 T+0；
8. 签到每天一次且只进入点击时的盘；
9. 普通礼包每账户一次，开发者礼包可重复，重试不重复到账；
10. 新礼包码可通过管理脚本新增；
11. 类型检查、自动化测试、生产构建和启动烟雾测试通过。
