# 东方财富真实行情接口与运维指南

## 1. 当前适配器

实现位置：

- `server/src/real-market/EastmoneyProvider.ts`
- `server/src/real-market/RealMarketRuntime.ts`
- `server/src/real-market/RealMarketRepository.ts`
- `server/src/real-market/db/`

当前报价端点：

```text
https://push2.eastmoney.com/webguest/api/qt/clist/get
```

不要改回探针中失败的单股端点：

```text
https://push2.eastmoney.com/api/qt/stock/get
```

探针环境里该端点在 1/5/10/20 QPS 均被远端断开。当前系统通过批量来源页刷新自选和持仓股票。

## 3. 全量发现

任何市场都必须先请求第一页并读取：

```json
{
  "data": {
    "total": 13677,
    "diff": []
  }
}
```

总页数只能这样计算：

```text
totalPages = ceil(data.total / configuredPageSize)
```

禁止通过固定三页、固定 300 只或固定 1200 只实现真实盘。

## 4. 历史接口

日 K：

```text
https://push2his.eastmoney.com/api/qt/stock/kline/get
```

分时：

```text
https://push2his.eastmoney.com/api/qt/stock/trends2/get
```

历史接口按股票详情页请求，不在首次启动时给三万多只股票批量下载全部历史。成功数据写入 `real_candles`，以后优先读本地缓存。

如果某市场接口不返回数据：

1. 保留已经缓存的真实历史；
2. 使用以后批量报价持续形成的真实分钟线/日线；
3. 返回清楚的 `notice`；
4. 不生成随机数据。

## 5. 本地测试

先运行独立探针：

```bash
python eastmoney_probe.py
```

再启动应用并观察：

```text
GET http://localhost:3100/api/real-market/status
```

重点字段：

- `instrumentCount`：本地活跃证券数；
- `markets[].providerTotal`：本轮接口总量；
- `completedPages / totalPages`：当前覆盖；
- `lastCompletedSweepDurationMs`：真实全量周期；
- `failedPages` 与 `lastError`：降级原因；
- `hotPageCount`：当前高优先级来源页数量。

## 6. 调优顺序

优先保持：

1. 无页面丢失；
2. 提供者不被过载；
3. 自选、持仓和详情页新鲜；
4. 再缩短全市场周期。

调优环境变量：

```text
REAL_MARKET_PAGE_SIZE
REAL_MARKET_CONCURRENCY
REAL_MARKET_FULL_SWEEP_MS
REAL_MARKET_HOT_REFRESH_MS
REAL_MARKET_HOT_PAGES_PER_ROUND
REAL_MARKET_REQUEST_TIMEOUT_MS
```

每次提高并发或页大小后，至少观察数十轮的失败率、P95 延迟、实际全量周期和数据库写入耗时。若页面失败增加，应降低并发，而不是丢弃失败页。

## 7. 更换数据提供者

新的提供者必须实现与 `EastmoneyProvider` 相同的边界：

- `fetchPage(market, page)` 返回提供者总量、证券和最新真实报价；
- `fetchHistory(instrument, range)` 返回真实分钟或日 K；
- 明确来源时间与本机接收时间；
- 保留来源原始价格并提供统一报价价格；
- 失败时抛出错误，不返回虚构数据。

替换提供者不应改变真实盘数据库、模拟交易账本、签到、礼包码和前端路由。
