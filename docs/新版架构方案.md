# 股票模拟器 2.0 重新开发架构方案

> 状态：虚拟市场闭环与独立真实行情模拟盘均已进入实现。
> 当前边界：原虚拟盘继续禁止联网；真实行情盘使用独立数据库和东方财富批量提供者，按接口 `total` 动态接入全量证券。探针的 1200 只样本不是产品上限。详细规则见 [真实行情模拟盘与奖励规则.md](./真实行情模拟盘与奖励规则.md)。
> 旧版不是作废代码。可继承算法与已确认缺陷见 [旧版算法审计与继承清单.md](./旧版算法审计与继承清单.md)。

## 1. 已锁定的产品定义

### 1.1 一个登录账户、两个独立模拟账本、两种显示币种

- 每个注册用户只有一个登录身份，但分别拥有“虚拟市场模拟盘”和“真实行情模拟盘”两个投资组合；
- 两个模拟盘使用物理独立数据库，现金、持仓、成交与结算互不串账；
- 账本基准币种固定为美元；
- 每个模拟盘首次创建时自动获得 **US$1,000,000** 初始模拟资金；
- 人民币显示按固定汇率 **1 USD = 7 CNY**，同一笔初始资产显示为 **¥7,000,000**；
- 美元/人民币按钮只是全局显示偏好，不是两个账户，不产生换汇交易；
- 切换显示币种后，所有市场的股价、资产、成本、成交额、手续费和盈亏一起换算；
- 换算不得改变现金、持仓数量、成本事实或总净值。

### 1.2 四个市场在同一个行情页面

- 虚拟盘固定展示沪深、港股、美股、英股共 1200 只股票；
- 真实行情盘按提供者每轮返回的 `total` 展示四个市场全部可用证券，不设置固定数量上限；
- 默认“全部市场”，可按沪深/港股/美股/英股筛选；
- 搜索、排序和分页跨市场共用；
- 不再按显示币种隐藏一半股票；
- 首页删除“数据库股票池 600 / 当前币种可浏览”；
- 首页删除资产摘要、持仓、成交和下单模块，只承担行情发现。

### 1.3 浏览公开，交易需要账户

- 未登录用户可以浏览首页行情和股票详情；
- 点击买入/卖出时才要求注册或登录；
- 注册完成后回到原股票和原交易意图；
- 账户详情统一承载资产总览、持仓、委托、成交、资金和盈亏；
- 不再像旧版一样把整个应用挡在登录页后面。

### 1.4 股票详情是核心工作台

点击任一股票进入 `/stocks/:instrumentId`，页面逐步具备：

- 股票名称、代码、市场、模拟状态、最新价和开高低等资料；
- 分时、日 K、月 K、年 K；
- 成交量、MA、MACD 等专业指标；
- 五档买卖盘、逐笔成交；
- 登录用户的当前持仓、平均成本、浮动盈亏、已实现盈亏；
- 市价、限价买卖和订单状态。

用户所说的 “MDA 图”首版按常见的 **MACD** 指标理解和实现。如果后续确认 MDA 是另一项指标，再单独增加，不影响当前图表数据模型。

## 2. 开发原则

1. **虚拟盘数据库是唯一股票源**：虚拟盘代码、名称、市场和初始价格以现有数据库为准，之后只由内部引擎推进；
2. **服务端权威**：浏览器不生成随机价格、K 线、盘口或成交；
3. **账本单一**：交易事实全部按 USD 定点金额保存，CNY 只做 7 倍显示；
4. **数据源严格隔离**：虚拟盘启动和运行均不访问行情网站；真实行情模拟盘只读取独立数据库，联网同步只能由显式启用的数据提供者执行；
5. **用户和 AI 同一套规则**：订单、撮合、手续费、现金、持仓和成交不得分成两套；
6. **逐步提高模拟真实性**：先完成正确闭环，再加限价簿、部分成交和更丰富的 AI 群体；
7. **每一步可验证**：构建通过不等于完成，关键账本和运行页面都要验证。

## 4. 金额与汇率模型

### 4.1 三层金额

为兼顾真实股票价格和统一账户，金额分成三层：

1. **来源价格**：抓取页面的原始币种，如 CNY/HKD/USD/GBP，只用于追溯；
2. **模拟报价价格**：当前虚拟行情的计价币种：
   - 沪深、港股使用归一化 CNY 报价；
   - 美股、英股使用归一化 USD 报价；
3. **账本金额**：成交时统一折算成 USD 入账。

固定转换：

```text
quoteCurrency = USD  → executionPriceUsd = quotePrice
quoteCurrency = CNY  → executionPriceUsd = quotePrice / 7

displayCurrency = USD → displayedMoney = moneyUsd
displayCurrency = CNY → displayedMoney = moneyUsd × 7
```

这样在人民币显示下，沪深股票接近原人民币价格，美股自动显示为美元价的 7 倍；切到美元显示后，所有股票又统一显示为美元。

### 4.2 成交审计

每笔成交同时保存：

- 原模拟报价和报价币种；
- 成交时的 `fxRateToUsd`；
- 每股 USD 成交价；
- USD 成交额、手续费和已实现盈亏；
- 显示币种不写入账本事实。

即使未来把固定汇率升级为动态汇率，历史成交仍可按当时汇率准确复算。本阶段固定 `fxRateToUsd(CNY) = 1/7`。

## 5. 数据模型

### 5.1 账户与资产

| 表 | 关键字段 | 说明 |
|---|---|---|
| `accounts` | id, username, passwordHash, displayName, displayCurrency, createdAt, lastLoginAt | 登录凭据和全局显示偏好 |
| `portfolios` | id, accountId, mode, initialCashUsd, availableCashUsd, frozenCashUsd | 用户和 AI 共用的虚拟投资组合；AI 的 accountId 为空 |
| `positions` | id, portfolioId, instrumentId, quantity, availableQuantity, frozenQuantity, averageCostUsd | 所有市场统一持仓 |
| `transactions` | id, portfolioId, instrumentId, actorType, actorId, side, quantity, quotePrice, priceUsd, feeUsd, realizedProfitUsd | 用户/AI 共用的不可变市价成交事实 |
| `position_settlement_lots` | portfolioId, instrumentId, quantity, unlockAt, settledAt, sourceTransactionId | 沪深 T+1 逐笔待结算批次 |

`orders`、`fills` 将在限价簿阶段加入；当前市价单直接原子生成 `transactions`，不伪装成已经存在完整限价撮合簿。

账户守恒条件：

```text
availableCashUsd + frozenCashUsd = portfolioCashUsd
availableQuantity + frozenQuantity = positionQuantity
totalAssetsUsd = portfolioCashUsd + Σ(positionQuantity × latestPriceUsd)
```

### 5.2 股票、行情与图表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `market_import_batches` | source, fetchedAt, marketCounts, fxRates, snapshotSha256 | 股票池导入可追溯 |
| `instruments` | symbol, name, market, sourceCurrency, quoteCurrency, lotSize, industry, liquidity | 股票元数据 |
| `quotes` | instrumentId, current/previous/open/high/low, volume, updatedAt | 当前权威快照 |
| `candles` | instrumentId, interval, bucketStart, open/high/low/close, volume | 分时和各周期 K 线 |
| `order_book_levels` | instrumentId, side, price, quantity, level, updatedAt | 可查询的盘口快照 |
| `market_trades` | instrumentId, price, quantity, aggressorSide, createdAt | 逐笔成交 |

历史保存策略：

- 数据库现有 1200 只证券及当前 `quotes` 是唯一行情起点，不再联网抓取或刷新股票池；
- 3 秒运行 tick 更新当前 quote，并由 `CandleService` 聚合实际运行数据；
- 当前分钟在内存持续更新，定时批量写 `candles`，分钟切换时立即完成上一根；
- 首次迁移只把数据库已有 quote 保存为 `DATABASE_SNAPSHOT`，不倒推、不伪造此前历史；
- 日 K 由实际记录持续更新，月 K/年 K只从数据库日 K 聚合；
- 不再把历史数组写入股票行 JSON；
- 图表缺数据或历史不足时原样返回，浏览器不允许随机补线；
- 当前需求明确冻结外部数据，任何行情同步脚本都不进入启动链路。

### 5.3 AI

| 表 | 关键字段 | 说明 |
|---|---|---|
| `ai_traders` | portfolioId, name, strategy, psychology, riskLevel, activityLevel, preferredMarket, nextActionAt, totalTrades, wins, losses | AI 档案和调度状态 |
| `portfolios` | id, initialCashUsd, availableCashUsd, frozenCashUsd | AI 与用户共用资产表 |

## 6. 虚拟市场算法

### 6.1 价格形成

旧版的“随机游走 + AI 压力 + 涨跌边界”继续作为骨架，但升级为：

```text
return =
  betaMarket × marketShock
  + betaIndustry × industryShock
  + idiosyncraticShock
  + liquidityAdjustedOrderFlow
  + meanReversion
  + optionalEventShock
```

- 默认每 3 秒一轮；
- 单 tick 默认限制在 ±0.35%；
- 市场、行业因子让同类股票具有相关性；
- 个股波动率和流动性来自股票档案；
- 用户/AI 净主动买卖量形成 `orderFlowImbalance`；
- 订单流影响按流动性归一化并随时间衰减；
- 日内边界按市场规则配置；
- 每个随机源可注入，以便确定性测试。

### 6.2 撮合路线

采用“做市商 + 中央限价簿”的混合模式：

- 合成做市商围绕理论中间价持续提供基础流动性；
- AI 和用户限价单进入同一订单簿；
- 市价单按盘口逐档吃单，允许多笔 fill 和部分成交；
- 限价单按价格优先、同价时间优先；
- 实际盘口直接供详情页五档买卖盘；
- 成交和未成交订单共同产生订单流信号；
- 在完整订单簿完成前，市价单仍可使用权威 quote 原子成交，但接口和账本按未来模型设计。

### 6.3 AI 群体

- [x] 默认持久化 5000 名，可通过 `AI_TRADER_COUNT` 配置；
- [x] 均衡、动量、逆向、价值、技术、稳健、进取七类可解释策略；
- [x] 依据真实标的的现价、昨收、日内位置、成交量、波动率和流动性评分；
- [x] 依据现金比例、单股仓位上限、最大持仓数、止损/止盈和风险等级决定买卖；
- [x] 按 `nextActionAt` 仅处理到期 AI，活动等级决定下一次决策时间；
- [x] 每笔 AI 市价单受每手股数、可用资金、可卖持仓和流动性参与上限约束；
- [x] AI 主动买卖量进入衰减订单流，影响下一行情 tick 和五档深度偏斜；
- [x] 排行榜按每个 AI 的实际现金、最新持仓市值和自身初始净值计算；
- [x] 到期 AI 批量更新调度状态，默认提高到高频轮询档位，并公开每分钟成交和待处理积压；
- [ ] LLM AI 暂未启用；数值策略本身不依赖外部模型或网络。

## 7. 交易规则

当前最小闭环：

- 四个市场都可用同一个 USD 模拟账户交易；
- 沪深、港股按 100 股整数倍，美股、英股按 1 股整数倍；
- 市价买卖；
- 交易表单按“手”自由输入，并可按可用资金/可卖持仓的 25%、50%、75%、100% 自动计算整手数量；
- 手续费默认成交额 0.03%，最低费用按账本 USD 配置；
- 买入成本包含手续费；
- 卖出记录已实现盈亏；
- 现金、持仓和成交在同一数据库事务内提交；
- 写接口使用幂等键，避免网络重试重复成交。
- 沪深为 T+1：买入立即计入总持仓，但进入 `position_settlement_lots`，下一交易日才增加可卖数量；
- 港股、美股、英股为 T+0：买入后立即可卖；
- 2026 年沪深交易日跳过周末和上交所公告休市日，不再按服务器午夜整仓重置。

完整虚拟交易随后加入：

- 可用/冻结现金和持仓；
- 限价单、撤单、部分成交、价格改善；
- 五档盘口和逐笔成交；
- 更长期年份的交易所休市日数据更新。

## 10. 外部行情冻结

- 不再开发东方财富、同花顺或其他行情探针；
- 不再更新 1200 只股票的身份和原始快照；
- `server/data/pgdata/` 是唯一数据源，数据库丢失时从现有备份恢复；
- `candles` 只记录数据库已有成交和此后内部模拟市场实际产生的 tick；
- 数据库起点以前的缺失历史保持缺失，不以随机序列回填。
